让团队的工作，
有一个自己的入口。

日常工作常常不在同一个地方：需求在消息里，进度在表格里，下一步记在某个人心里。MIAO 的方向，是让小团队能把这些真实流程整理成自己掌握的内部应用。

从重复，而不是从软件开始

挑一件经常发生、又需要多人接续的工作：客户沟通、采购申请、项目进度，或内部需求收集。先说清楚谁在做、要留下哪些信息、下一步怎么交接。工具应跟着这套工作长出来，而不是先要求团队适应一套固定系统。

在 Agent-first 的产品体验中，fx 会围绕这些目标提出必要的问题，整理一份应用草稿。团队能先预览页面和操作，再决定是否发布。发布后的应用承接日常填写、查询和状态更新；需要核对或修复时，才打开底层数据视图。

一条可理解、可确认的工作路径

  1. 描述要完成的工作。从业务目标和当前阻碍开始，不必先学习数据库或页面搭建器。
  2. 检查方案和预览。确认需要的页面、记录和动作。修改先形成草稿，团队可以继续沟通与查看。
  3. 确认后交给团队使用。发布是有意为之的动作。日常用户在业务页面做事，不必每一步都和 AI 对话。
  4. 需要排查时查看数据。数据表是检查、导出和必要修正的入口，不是用户进入应用时的默认界面。

这个流程是 MIAO 的产品目标。页面生成、版本化预览和发布目前仍在规划与分阶段开发中；今天的产品还不能仅凭一句描述生成完整业务应用。

今天可以用 MIAO 做什么

当前版本已提供工作区、成员与邀请、应用和数据表管理、记录的新增编辑与查询、应用级访问权限，以及操作日志和数据导出。fx 在受支持的浏览器中运行，可通过当前工作区获授权的数据工具协助整理表结构与记录。团队也可自行部署代码和后端服务。

因此，现阶段更适合把 MIAO 当作一套可自托管的轻量数据工作台，并在 fx 协助下处理数据。它还不是成熟的无代码建站工具，也不会把任意 AI 生成代码直接作为应用运行。

把控制权留在团队手里

MIAO 是开源软件。团队可以检查代码，选择自己的部署方式，并管理业务数据所在的后端。服务端对工作区成员和应用访问逐请求校验；浏览器中的 fx 只能使用应用明确交给它的上下文和工具。

自托管也意味着部署方需要维护服务器、域名、备份和恢复流程；启用 AI 时，还要配置自己的 AI Gateway 服务并承担供应商费用。软件不收平台年费，不代表运行基础设施没有成本。

目前的边界

  • 自然语言生成业务界面、草稿版本、应用预览与发布是产品规划，不应视为当前已上线能力。
  • fx 需要可用的服务端 AI Gateway 配置；嵌入式浏览器执行需要支持 JavaScript Promise Integration（JSPI）的浏览器。
  • 此 Vercel 站点提供官网和静态文档；账号、应用 API 与 PocketBase 需要单独部署和配置。
  • 代码已实现的功能仍需在目标环境按真实账号、权限和运行配置验收后，才能作为生产可用承诺。

能力状态依据 MIAO 仓库 2026-09-29 的代码评审和产品方案整理。产品规划与已实现能力分别标注，部署环境可能影响实际可用性。
