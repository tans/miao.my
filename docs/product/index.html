把分散的日常工作，
整理成团队自己的应用。

日常工作常常不在同一个地方：需求在消息里，进度在表格里，下一步记在某个人心里。MIAO 的方向，是让小团队能把这些真实流程整理成自己掌握的内部应用。

先从团队反复处理的工作开始

挑一件经常发生、又需要多人接续的工作：客户沟通、采购申请、项目进度，或内部需求收集。先说清楚谁在做、要留下哪些信息、下一步怎么交接。工具应跟着这套工作长出来，而不是先要求团队适应一套固定系统。

按照 MIAO 计划中的使用方式，fx 会围绕这些目标提出必要的问题，并整理成应用草稿。团队能先预览页面和操作，再决定是否发布。团队发布后，就可以用应用录入信息、查询记录和更新进度；需要检查或修正数据时，再打开数据表。

从描述需求到团队开始使用

  1. 描述要完成的工作。从业务目标和当前阻碍开始，不必先学习数据库或页面搭建器。
  2. 检查方案和预览。确认需要的页面、记录和动作。修改先形成草稿，团队可以继续沟通与查看。
  3. 确认后交给团队使用。发布前由用户确认。团队成员在业务页面处理日常工作，不必每一步都找 AI 助手。
  4. 需要排查时查看数据。数据表是检查、导出和必要修正的入口，不是用户进入应用时的默认界面。

这个流程是 MIAO 的产品目标。自动生成页面、草稿预览和发布仍在分阶段开发；今天的产品还不能仅凭一句描述生成完整业务应用。

今天可以用 MIAO 做什么

当前版本支持工作区、成员邀请、应用和数据表管理、记录的新增、修改和查询、应用访问权限、操作日志及数据导出。MIAO 内置 AI 助手 fx，可在受支持的浏览器中使用当前工作区授权的数据工具，协助整理表结构和记录。团队也可以自行部署 MIAO 和后端服务。

现阶段，团队可以在自行部署的 MIAO 工作区中管理业务数据，并让 fx 协助处理表格和记录。自动生成完整业务页面仍在建设中；MIAO 不会直接运行 AI 随意生成的代码。

应用和数据，由团队自己管理

MIAO 是开源软件。团队可以检查代码，选择自己的部署方式，并管理业务数据所在的后端。服务端会在每次请求时检查工作区成员身份和应用访问权限；浏览器中的 fx 只能使用应用明确交给它的上下文和工具。

自行部署也意味着团队要维护服务器、域名、备份和恢复流程。使用 AI 时，还需配置 AI Gateway 并支付相应服务费用。软件不收平台年费，不代表运行基础设施没有成本。

目前的边界

  • 用自然语言生成业务页面、预览草稿和发布应用仍在开发中，尚未作为当前可用功能提供。
  • fx 需要可用的服务端 AI Gateway 配置；嵌入式浏览器执行需要支持 JavaScript Promise Integration（JSPI）的浏览器。
  • 此 Vercel 站点提供官网和静态文档；账号、应用 API 与 PocketBase 需要单独部署和配置。
  • 代码已实现的功能仍需在目标环境按真实账号、权限和运行配置验收后，才能作为生产可用承诺。

能力状态依据 MIAO 仓库 2026-09-29 的代码评审和产品方案整理。产品规划与已实现能力分别标注，部署环境可能影响实际可用性。
