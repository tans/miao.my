# MIAO 用户手册

把团队的工作变成自己的应用。本手册面向企业负责人、应用创建者、工作区管理员和日常使用成员，按实际使用顺序说明如何创建、发布、使用和管理应用。技术架构放在最后的附录。

## 认识 MIAO

MIAO 用于建立和使用企业内部应用。你向内置 Agent（fx）说明工作目标，它帮你整理页面、数据和操作；确认后发布给团队。成员打开应用，直接使用表单、列表、详情和任务页面处理工作。

**三种操作各有入口：**

1. **管理应用：**告诉 fx 要创建或修改什么，检查草稿并确认发布。
2. **使用应用：**在已发布的业务页面录入、查询和处理记录。
3. **检查数据：**需要核对或修正底层记录时，从应用菜单打开“查看数据表”。

例如客户跟进、采购申请、项目事项和内部需求收集，都可以从一项反复发生的工作开始。不必先画页面、建字段或拖拽组件；先说清楚谁参与、要记录什么、下一步如何推进。

| 角色 | 主要工作 | 建议阅读 |
| --- | --- | --- |
| 应用创建者 | 描述需求、检查预览、发布和调整 | 创建应用至修改应用 |
| 业务成员 | 录入、查询、处理和核对业务数据 | 团队日常使用、数据、常见问题 |
| 工作区管理员 | 邀请成员、分配权限、查看用量和日志 | 成员与权限、企业治理 |
| 企业负责人 | 确定应用责任、数据规则和运营方式 | 认识 MIAO、成员与权限、企业治理 |

## 开始使用

1. 使用企业提供的 MIAO 地址注册或登录。收到邀请时，用受邀邮箱接受；需要验证邮箱时，先完成验证。
2. 登录后选择工作区。个人工作区用于自己的应用；加入企业工作区后，按企业授予的权限协作。
3. 在首页输入想建立的应用，或从应用列表打开已有应用。最近使用的应用排在前面；应用较多时可搜索和排序。

切换工作区后，页面只显示新工作区中你有权访问的应用。收藏的旧链接也会重新检查权限。看不到应用时，先确认工作区，再请负责人检查访问授权。

### 选择第一个需求

推荐从一个边界清楚、能反复使用的流程开始。准备三句话：**谁在做、每次要记录什么、完成的标准是什么。**例如：“销售记录客户及下次联系日期；负责人每天查看待跟进客户；主管能看到本周进展。”

## 创建应用

1. 在工作区首页的输入区说明目标，也可以补充现有表格、字段清单或业务规则。
2. fx 围绕对象、操作、参与人和结果追问必要问题。你可以直接回答，也可以指出它理解错的地方。
3. 查看方案中的应用名称、主要页面、要保存的数据、成员可执行的动作及可见范围。
4. 继续用自然语言调整，例如“增加下次联系日期”“销售只能看自己的客户”“主管需要本周待办”。确认方向后生成草稿。

> **可以直接这样说：**“为 8 人销售团队做一个客户跟进应用。销售录入客户、联系人、最近沟通和下次跟进时间；主管查看本周待跟进与逾期项；不要让其他销售看到我的私人备注。”

描述规则时尽量说明例外：谁可以删除记录、离职成员的客户如何交接、哪些信息只能由主管查看。fx 可以建议页面和字段；涉及数据删除或扩大可见范围的操作会要求单独确认。

### 草稿包含什么

草稿保存应用页面、字段、动作与展示规则，并附上变更摘要。你可以反复让 fx 修改。草稿不会自动替换团队正在使用的版本；预览中展示的示例记录会明确标记。

## 预览与发布

1. 打开“预览”，逐页检查导航、列表、详情和表单。用示例记录验证页面是否符合实际工作。
2. 检查必填项、字段名称、筛选条件、操作按钮、不同角色能看到的内容，以及手机上的体验。
3. 阅读发布卡中的变更摘要。若包含字段迁移、批量改写或权限扩大，核对受影响的对象和记录。
4. 有发布权限的人员确认“发布”。成功后，成员通过稳定的应用链接进入正式业务页面。

预览不会隐式写入正式记录。正式页面只显示已发布版本；发布失败时团队继续使用原版本，草稿保留供你修正。尚未发布的应用标为草稿，不显示为运行中。

### 发布前检查

- 一名实际业务成员能独立完成“打开 → 找到记录 → 处理 → 保存”的流程。
- 查看与编辑权限符合团队分工；敏感字段和附件没有暴露给无关人员。
- 示例数据与真实数据区分清楚；没有真实记录时显示空状态。
- 应用负责人知道如何处理错误、授权请求和下一次修改。

## 团队日常使用

打开应用后，默认看到已发布的业务界面。页面导航由实际工作决定：可能是总览、客户、跟进任务，也可能是申请、审批或项目事项。日常操作直接在页面完成，无需向 fx 发每一条指令。

### 查找与处理记录

1. 在列表中搜索、筛选或排序，打开详情确认上下文。
2. 点击应用中的按钮新增记录、修改内容、更新状态或上传附件；关联记录从授权范围内选择。
3. 保存后确认结果提示。验证失败时按字段提示修正；网络失败时未提交输入保留，重试不会无故生成重复记录。

指标、待办和列表来自当前有权访问的真实数据。没有记录时页面会说明空状态；没有写权限的成员不会看到可执行的编辑操作。删除等不可恢复的动作会展示对象和影响，并要求确认。

### 专注使用与分享

“打开应用”进入专注使用模式，隐藏管理侧栏和对话，保留返回工作台的入口。把应用链接发给同事后，同事仍需登录并获得访问权限；链接本身不会授予权限。

## 修改应用与版本

进入应用页，向右侧 fx 描述修改。它会读取当前应用和页面上下文，给出差异摘要与新草稿。例如：“在客户详情增加最近一次联系结果，并把逾期客户放在总览最上方。”

1. 确认变化会影响的页面、字段、动作和人员。
2. 试用草稿预览；必要时继续对话修改。
3. 检查数据迁移和权限影响，确认发布。已经打开表单的同事会收到新版提示，可先保存当前工作。

“变更历史”记录发布人、时间、摘要和版本。界面改动可以在兼容的数据结构上切回旧版；切回界面不会撤销成员已经录入的业务记录。修改涉及删除字段、迁移或批量改写时，先查看影响说明和备份，再按提示处理。

两人同时修改时，旧草稿不会静默覆盖新版本。系统提示重新对照当前版本处理冲突。暂时不使用的应用可以归档；永久删除会显示受影响的数据和附件。

## 数据、附件与导出

从应用右上角“··· → 查看数据表”进入检查页。按表、记录逐层查看，可搜索、筛选、排序和分页。具有相应权限的成员可进入编辑状态修正单条记录；保存结果会明确提示。

如果要新增字段、调整页面或修改业务规则，直接告诉 fx。数据表检查页用于核对和必要修正，不承担应用搭建流程。普通成员首次进入应用看到的是业务界面，而非表结构。

### 附件和关联记录

上传时按字段提示选择文件；下载需要对应用和记录有访问权限。关联选择只显示当前应用中有权访问的记录。附件不会因为有人知道文件地址而变成公开资源。

### 批量导入与导出

批量导入先检查字段映射、预览样本和错误行，再确认写入。导入结果给出成功数、失败数及来源位置；重复提交可按同一任务查询结果。工作区导出仅包含发起者有权访问的数据；导出文件按企业内部数据要求保存和传递。

## 成员与权限

工作区 owner 管理成员和应用访问范围；admin 协助邀请与日常管理；member 使用授予的应用。每个应用还可以分配 viewer、editor 和应用管理权限。工作区角色不自动等于所有应用的发布或编辑权限。

| 需要完成的事 | 由谁处理 |
| --- | --- |
| 邀请同事进入工作区 | 工作区 owner 或 admin |
| 设置应用可见人员 | 工作区 owner |
| 阅读授权记录 | 应用 viewer 及更高业务权限 |
| 新增、修改业务记录 | 应用 editor 或具有相应操作授权的成员 |
| 发布和回退应用 | owner 或明确授予权限的应用管理者 |
| 查看平台总体状态 | 平台管理员；不因此获得业务内容访问权 |

邀请链接与指定邮箱绑定，并有有效期。移出某工作区只撤销该空间的访问，不停用同事的整个账号。成员离职或岗位变化时，先调整应用责任和记录归属，再移除访问。权限调整后，旧页面、链接与 fx 对话中的访问都要重新验证。

### 对话与变更的可见范围

个人与 fx 的对话正文默认仅本人可见；应用版本的变更摘要供有权管理应用的人查看。涉及业务记录的操作按实际操作者身份留痕，fx 不能绕过成员权限。

## 企业治理

### 应用责任

为每个应用指定业务负责人：谁审核需求、谁发布变更、谁处理授权、谁定期检查数据质量。先从小范围团队试用，再扩大使用人员；变更前告知受影响成员。

### 用量与预算

空间设置提供 AI 请求和 token 用量及预算控制。请求次数、token 数和实际账单是不同口径；费用结合所使用的 AI 服务结算记录核对。业务页面在 AI 服务不可用时继续使用，创建或修改应用则显示恢复提示。

### 审计与数据保护

操作日志帮助负责人查询谁在何时修改应用或记录、结果如何。日志不包含完整敏感字段、密钥或私人对话正文。平台管理员维护账号、配置和总体服务，但不会因管理平台就直接读取企业业务记录与附件。

### 自托管责任

采用自托管时，企业指定维护人负责域名与 HTTPS、账号策略、邮件投递、备份和异地副本，并定期在隔离环境验证恢复。删除账号、应用或字段前，确认保留策略和受影响数据。

## 常见问题

### 同事打不开应用

确认已登录正确邮箱、选择正确工作区，再请 owner 检查应用访问名单。转发链接不会自动授予权限。

### 草稿变化没有出现在正式应用

草稿与预览独立于正式版本。检查发布状态与变更历史；发布失败时可查看原因、修改草稿并重新发布。

### 保存记录失败

检查字段提示、权限和网络状态。发生记录冲突时，重新读取最新内容后再保存；不要用刷新丢弃未提交输入。

### fx 无法回答或额度用尽

查看工作区 AI 状态和预算，联系管理员检查服务配置。已发布应用仍可正常处理业务。

### 找不到数据表

先进入相应应用，从“··· → 查看数据表”打开。要改字段或页面时，在应用中告诉 fx。

### 误发布或误删内容

先停止进一步修改，查看变更历史。兼容的界面版本可回退；业务记录与已删除的数据按审计和企业备份流程处理。

## 完整示例

**客户跟进应用：**

1. **发起：**负责人描述“销售录入客户、安排下次联系；主管看本周待跟进”。fx 澄清销售之间的可见范围和逾期定义。
2. **预览：**草稿包含客户列表、客户详情、跟进表单和主管总览。负责人试用新增客户、筛选逾期及手机界面。
3. **发布：**负责人确认权限与页面，发布应用并邀请销售和主管。销售以 editor 身份录入，主管查看团队总览。
4. **迭代：**一周后要求加入“联系结果”和“下次动作”。fx 给出字段及页面变更摘要；负责人预览、确认并发布。
5. **治理：**成员离职时先交接客户，再移除其工作区权限；通过审计核对关键修改，定期导出或备份。

同一方法适用于需求收集、项目事项和采购申请：先定义真实的业务闭环，再逐步增加页面与规则。

## 附录：技术架构

本节供企业技术负责人评估部署与数据边界。日常使用无需了解这些内部组件。

| 组成 | 职责 | 企业关注点 |
| --- | --- | --- |
| 浏览器工作台与 fx | 展示应用、承载对话与受控工具调用 | 只访问当前会话获授权的数据；浏览器支持 fx 所需运行能力 |
| MIAO API | 处理身份、工作区、应用、业务记录和版本发布 | 每次请求校验成员和应用权限 |
| PocketBase | 保存账号、应用定义、业务数据与附件 | 数据目录、访问控制、备份与恢复由部署方管理 |
| AI Gateway 代理 | 转发 fx 的模型请求并记录用量 | 长期密钥留在服务端；AI 故障不阻断已发布应用 |
| 静态官网与文档 | 提供公开介绍和本手册 | 与企业业务服务分开部署 |

模型生成的界面定义先经服务端验证，再由受控运行时渲染；正式应用固定引用已发布版本。草稿、预览和发布各有边界。平台管理与企业工作区数据分开，附件下载也需要重新授权。自托管团队应完成 HTTPS、密钥管理、备份、异地复制和恢复演练。

源码和部署命令见 [MIAO 应用仓库](https://github.com/tans/miao)。本网站仓库只承载官网和用户手册。
