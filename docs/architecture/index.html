让每一层，都只负责该做的事。

MIAO 把静态官网、应用界面、业务 API、数据存储和 AI 服务分开。这样团队可以单独部署公开页面，也能在运行应用时保留明确的数据访问边界。

一次请求经过哪些部分

  1. 浏览器：承载登录后的 MIAO 工作台和 fx。浏览器只获得当前会话和界面所需数据。
  2. MIAO API：由 Fastify 提供账号、工作区、应用和记录接口。每次请求都会重新检查成员关系、应用访问和操作权限。
  3. PocketBase：保存身份、工作区关联、应用元数据、数据表和业务记录。
  4. AI Gateway：fx 的模型请求经 MIAO 服务端代理转发。Gateway 长期密钥由服务端配置，浏览器不会获得该密钥。

fx 可以访问哪些信息

fx 通过浏览器内的 WebAssembly SDK 运行。MIAO 为它提供界面、当前工作区上下文和受限工具；工具请求仍通过 MIAO API 授权。它不会继承 fx CLI 的文件系统、Shell、系统密钥链或 MCP 配置，也不会一次性读取所有业务记录。

fx 要在浏览器中运行，浏览器需支持 JavaScript Promise Integration（JSPI）。如果浏览器不支持，或服务端没有配置 AI 服务，用户仍可手动管理数据，但无法使用 fx 对话。

官网与 MIAO 应用需要分别部署

本 Vercel 项目包含官网和产品文档，发布为静态文件。它不提供账号、业务 API、数据库，也不代管 AI Gateway 密钥。完整 MIAO 应用还需要部署 Fastify API 与 PocketBase，并按实际域名配置浏览器访问策略。

自行部署的团队需要负责 HTTPS、服务运行、备份和异地副本，并定期在隔离环境中演练数据恢复。API、数据库、AI 服务费用和邮件发送也取决于具体部署配置。

当前功能与开发中的功能

自然语言生成业务页面、预览草稿、发布新版本和切回旧版，都需要有版本管理的应用运行环境与服务端校验，不能只靠官网静态页面或前端设置实现。规划细节和当前功能边界见产品说明。

架构说明依据 MIAO 当前代码与部署形态整理。生产环境仍需独立验收权限、AI 配置、跨工作区隔离和备份恢复。
