从一个需求，到持续运行的内部应用

以下界面为静态产品原型，所有记录、数量和状态均为示意内容。

01 · Describe

描述工作，也描述边界

告诉小助手谁在使用、需要哪些字段、怎样流转状态，并补充文件或回答追问。从客户跟进、订单处理等具体工作开始。

当前边界：需求需要澄清；对话不会跳过审批直接成为正式应用。

准备第一个需求静态原型 →创建文档 →

02 · Shape

生成受控结构，检查界面草稿

服务端 Agent 生成数据结构和界面草稿。检查字段白名单、业务动作、状态转换与成员范围，再预览和确认发布。

当前边界：使用受控 schema 和界面组件；预览不隐式写入正式记录，不执行任意用户源码。

检查发布流程静态原型 →架构文档 →

03 · Use

在工作区里处理真实工作

团队在已发布应用中搜索和编辑记录、处理表单与状态流；需要检查底层数据时，进入数据表、记录详情与授权导出。

当前边界：同事必须登录并获得访问权限；知道链接不会获得记录或附件权限。

了解团队协作静态原型 →数据文档 →

04 · Operate

让授权的工作持续运行

配置定时或事件触发的后台任务、声明式采集和通知，查看运行回执与失败原因。公开只读页仅展示明确授权的记录字段和图片。

当前边界：采集只读取无凭据的 HTTP(S) 来源；任务不能扩大授权。自托管者负责模型配置、备份和运维。

了解后台任务静态原型 →运维文档 →
