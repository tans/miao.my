SELF-HOSTING · COSTS & DEPENDENCIES

What to prepare before deploying, and who pays

MIAO source is licensed under Apache License 2.0 and the software itself is free; but in a self-hosted deployment the server, domain, backups, model inference and mail service are prepared and paid for by the operator. This page lists each dependency's purpose, who configures and pays, and what breaks without it. Every claim traces to the LICENSE, the operations guide, or vendor pages (checked 2026-10-12). This page offers no MIAO commercial plans and no quotes.

What is limited without a model or Jev

AI that is unconfigured, disabled, or blocked by budget is rejected before a request record is created; failed calls and connection checks also consume budget:

  • Works without any model once configured: sign-in and permissions, manual data table and record management, status flows, background jobs within existing authorization, published public-page reads.
  • Without an LLM generation model: assistant proposals and UI drafts for open-ended requests are unavailable.
  • Without a JEV decision model: candidate selection and decision validation are unavailable; conversational app building, UI edits and publication decisions (the public scope in a publish candidate is decided by Jev) cannot proceed.
  • Without a mail service: registration verification and invitation emails are affected, as above.

Pre-deployment checklist

  1. Server account and target environment (Linux/macOS x64/ARM64 with PM2, curl, openssl).
  2. First platform admin email and the MIAO_SETTINGS_ENCRYPTION_KEY (without it server-side keys cannot be saved or read; a fresh install needs only data dir, port, encryption key and admin email).
  3. Model accounts: provider, base_url and API keys for both LLM and JEV; set workspace daily budget caps before opening up.
  4. Resend account with a verified sender domain (if you need verification or invitation emails).
  5. Domain and HTTPS reverse proxy.
  6. Backup space, schedule and off-site copies (scripts do not create them), plus one person responsible for upgrades, restore drills and availability.

Operator responsibilities

Upgrades and rollback, backup and restore verification, HTTPS and availability are the operator's responsibility. The release script switches back to the previous release if startup or health checks fail, but the database is never rolled back automatically; keep a fresh backup and rehearse restores in an isolated environment. A 200 health response does not validate models, mail or the production domain.
