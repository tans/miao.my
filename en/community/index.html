SECURITY

Do not paste security issues in public.

Never include tokens, passwords, internal addresses, complete production data or unredacted attachments in an issue, discussion or log. Prefer GitHub Security Advisories; if the repository does not show a private report entry, contact the maintainers to confirm a private channel.

Open private security report ↗

Support boundaries

  • Public support: docs, reproducible problems, code collaboration and release notes.
  • Self-hosting responsibility: model configuration, backups, credentials, networking and on-site operations stay with the deployer.
  • Upstream services: model, Jev, mail and paid API quotas or authorization require separate acceptance.
  • Response expectations: issues are triaged by reproducibility, impact and maintainer time; no enterprise SLA is promised.
