COMMUNITY / SUPPORT

遇到问题，从一条可复现的信息开始。

这里是 MIAO 的公开协作入口：先读文档，再选择合适的 Issue、讨论或发布记录。MIAO 是开源、自托管项目，社区协作不等同于企业 SLA。

查看 Issues ↗先读文档

选择正确的入口

BUG

报告可复现的问题

请附上最小复现步骤、MIAO 版本或 commit、浏览器/系统环境，以及已脱敏的错误片段。

新建 Issue ↗

IDEA

提出功能建议

说明要解决的工作问题、受影响的角色和可接受的边界。先确认它不是现有文档或开放 Issue。

参加 Discussions ↗

SELF-HOSTING

排查部署问题

先看自托管、运维和发布文档，再提供部署方式、commit、日志摘要和可复现命令。

查看自托管文档

RELEASES

确认版本与变更

使用发布记录和 changelog 对齐版本、兼容性和回滚边界，不把本地成功当成生产验收。

查看 Releases ↗

SECURITY

安全问题不要公开粘贴。

不要在 Issue、Discussion 或日志中提交 token、密码、内部地址、完整生产数据或未脱敏附件。优先使用 GitHub Security Advisories 的私密报告入口；如果仓库没有显示该入口，请先联系维护者确认私密通道。

打开私密安全报告 ↗

支持边界

  • 公开支持：文档、可复现问题、代码协作和发布说明。
  • 自托管责任：模型配置、备份、凭据、网络和现场运维由部署方负责。
  • 上游服务：模型、Jev、邮件或付费 API 的配额与授权需要单独验收。
  • 响应预期：Issue 会按可复现性、影响范围和维护者时间排序，不承诺企业 SLA。
